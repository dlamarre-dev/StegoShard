# Claims and evidence register

No security or resilience claim should be strengthened in release copy without adding
evidence here. “Pending” claims are design goals, not release guarantees.

| Claim                                                                                           | Evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Status / limitation                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Core processing is local and makes no network requests                                          | Manifest tests, package scan, CSP `connect-src 'none'`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Verified for public builds; hosted code delivery remains a trust surface. `stegoshard ui` (npm CLI) and the offline bundle's `serve.mjs` **listen** on 127.0.0.1 when asked; still no outbound request, and the released binaries hold no network permission at all                                                                                                                                                                                                                                                                                                                                                                          |
| Confidentiality uses Argon2id and AES-256-GCM                                                   | `SPEC.md` §§5–6, crypto vectors, TS/Python conformance; AES-256-GCM, SHA-256 and HMAC-SHA256 additionally checked against NIST CAVP and Wycheproof vectors via crypto-condor (`tests/compliance`)                                                                                                                                                                                                                                                                                                                                                                                | Independent audit pending. The third-party vectors cover AES-GCM and the hashes only: **Argon2id and HKDF have no such coverage**, since crypto-condor has no module for either. Their evidence remains the two implementations agreeing on frozen vectors                                                                                                                                                                                                                                                                                                                                                                                   |
| Sampled `randomBytes` output passes the NIST battery within a calibrated tolerance              | NIST battery (TestU01) over 8 MiB with the user-entropy layer off, rich, and degenerate (`tests/compliance/test_randomness.py`)                                                                                                                                                                                                                                                                                                                                                                                                                                                  | A smoke test for detectable distribution defects, nothing more. It does **not** establish unpredictability, which no statistical battery can: a counter encrypted under a fixed key passes them all. It does not simulate a failed CSPRNG. And it is **not evidence about steganographic detectability**: steganalysis compares a carrier against a natural-image model, where a uniformly random bit-plane is itself a tell                                                                                                                                                                                                                 |
| A cover photo reused under one password is refused rather than silently leaked                  | SPEC §5.3/§5.4 state it as a **MUST NOT**; `src/core/stego-guard.ts` refuses a second embed into the same cover content under the same password and Argon2id parameters with `STEGO_COVER_REUSE`, on every embed path (CLI, extension, web app, MCP, library), overridable only per call (`--allow-cover-reuse`); `src/core/stego-guard.test.ts` covers both carriers and every allowed case, and `src/core/stego.binding.test.ts` measures the leak the rule prevents (one payload bit flipped moves exactly one image bit under reuse, against 763 under a different password) | **In-memory and realm-scoped, by design.** It catches reuse within one process or page session and nothing else: a save tomorrow, a save on another machine, or a second pristine copy of the same photograph is invisible to it. A durable registry would catch those and would be a file on disk proving stego covers exist, refused here for the same reason `--export-number` is refused on deniable paths. The map is bounded and evicts oldest-first, so a run embedding into thousands of distinct covers forgets the earliest. The constraint remains the operator's to keep; this is a backstop, not a proof                        |
| Unlocking is deliberately expensive: Argon2id at 256 MiB, 4 passes, run exactly once per unlock | `DEFAULT_ARGON2` (`src/core/crypto.ts`), frozen and mirrored in `python/stegoshard/`; `SPEC.md` §5.1 and §11; the once-per-unlock count is asserted on every pull request (see [CRYPTO-REVIEW.md](CRYPTO-REVIEW.md) §5.7); `npm run spec:check` pins the documented figures to the constant and `npm run golden:check` refuses a change to it without a `FORMAT_VERSION` bump                                                                                                                                                                                                    | **A hard floor with no fallback.** There is no low-memory profile, no device detection and no degraded mode: a device that cannot allocate 256 MiB cannot open a vault, and the failure is an allocation failure rather than a recoverable one. This is an **availability** limitation, not a confidentiality one, and it is not measured across low-memory mobile browsers. It is also not freely fixable: on the stego, gallery and slot-KEK paths the cost is not stored (see [VERSIONING.md](VERSIONING.md)), so a cheaper profile would be a second format on the paths least able to afford a distinguisher — which is why none exists |
| Malformed input is resource-bounded                                                             | Parser tests, fuzzing, browser preflight and post-decode caps                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    | Browser limits differ from the 1 GiB CLI binary limit                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Missing image shards can be recovered                                                           | Reed–Solomon property and pipeline tests                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         | Only within the encoded `m` parity budget                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Generated disk images round-trip losslessly                                                     | Post-save verification and codec tests                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           | Does not prove survival through arbitrary third-party processing                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Printed recovery survives supported capture conditions                                          | `docs/QA.md` physical matrix                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     | **Pending physical sign-off; do not advertise as a universal guarantee**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Deniable paths avoid explicit mode/region errors                                                | Access-structure tests and fixed candidate schedule                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | Not a formal timing, forensic-indistinguishability, legal, or coercion guarantee                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Deniable carriers survive off-the-shelf triage                                                  | zsteg differential test over four CC0 photographs: the carrier presents the same structural findings and text-fragment counts as the untouched cover (`tests/steganalysis`)                                                                                                                                                                                                                                                                                                                                                                                                      | PNG carriers only; the JPEG carrier has a separate and narrower measurement, in the row below. StegExpose additionally shows the carrier scoring identically to a clean cover (0.031-0.096), but at 0.035% embedding that is below the detectors' sensitivity, not evidence of resistance to steganalysis                                                                                                                                                                                                                                                                                                                                    |
| The JPEG carrier does not move a JPEG steganalyser                                              | Aletheia over five camera originals: on the two covers where an outguess control is demonstrably detected in CI, the carrier scores within the 0.1 reporting granularity of its untouched cover (identical on four of five covers; `beach` moves 0.1 to 0.2) (`tests/steganalysis`, nightly)                                                                                                                                                                                                                                                                                     | Rests on **one** working detector over **two** covers: three of Aletheia's four saturate on this set, flagging clean photographs. The detectors are learned, so a low score may mean undetectable **or** outside the training distribution. Not a general claim of resistance to JPEG steganalysis                                                                                                                                                                                                                                                                                                                                           |
| New credentials meet a 12-character minimum                                                     | `meetsPasswordFloor` + policy tests; enforced on every save/key-creation surface and not waivable by `--allow-weak-password`                                                                                                                                                                                                                                                                                                                                                                                                                                                     | A length floor, not a strength guarantee: `aaaaaaaaaaaa` clears it. The advisory tier (16+ chars, 80+ estimated bits) warns but is dismissible by design. Existing vaults created under the old policy still open; restore deliberately does not apply the floor                                                                                                                                                                                                                                                                                                                                                                             |
| The erasure code is the construction the specification describes                                | The Cauchy matrix, the Gauss-Jordan inverter, the MDS property and the frozen parity bytes checked against `galois`, a finite-field linear-algebra engine, over all 192 layouts the encoder produces, k=1 to the Gallery maximum of 190 plus the two colour-grid layouts, on every pull request (`tests/erasure`)                                                                                                                                                                                                                                                                | Establishes that the specification, both implementations and an independent engine agree. Does **not** establish that the formula is a sound design choice: transcribing SPEC §7.4 into the reference is a human act, and a specification wrong in the same way as the code would pass. MDS is exhaustive on 13 of the 192 layouts and sampled on the rest (26,359 submatrices in total), since `C(154,135)` has 33 digits. For a Cauchy matrix MDS is a theorem, so the sweep guards the implementation rather than proving the property                                                                                                    |
| The Galois field under erasure coding is the one the specification names                        | Both stacks compared exhaustively on every pull request (`tests/erasure`): the 65,536 products against reedsolo **and** against a table-free carry-less multiply; the 65,280 quotients, 255 inverses and exp/log tables against reedsolo alone                                                                                                                                                                                                                                                                                                                                   | Anchors the **field only**; this row on its own says nothing about the code built on it, which is covered by the row above. reedsolo is an independent implementation, not a standards authority: there are no standardised vectors for this 0x11D field, unlike the 0x11B field of AES                                                                                                                                                                                                                                                                                                                                                      |
| Independent recovery remains possible                                                           | Python decoder and fresh-fixture CI conformance                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  | Current format is a pre-1.0 candidate until audit closure                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| The MCP server opens no socket and makes no network request                                     | stdio transport only; a source-scan test asserts `src/mcp/**` imports none of `node:net`/`node:http`/`node:https`/`node:dgram`/`node:tls`, calls no `fetch` and opens no server (`src/mcp/server.test.ts`); the released binaries still hold no network permission                                                                                                                                                                                                                                                                                                               | Says nothing about the **agent** connected to it, which _is_ a network client: tool arguments and results may leave the machine and be retained by a model provider. Path confinement (`--root`) is a policy in the server, not a runtime sandbox, since `deno compile` grants blanket read/write. Unstable interface in 0.9.x                                                                                                                                                                                                                                                                                                               |
| No analytics, telemetry, or host permissions ship                                               | Source scan, manifest/package checks, privacy policy                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Downloaded release provenance must still be verified: the source scan speaks for the source, not for the binary you fetched. See [Verify your download](CLI.md#verify-your-download) and the release-integrity row below                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Every AEAD site binds its container context                                                     | AAD on the §6 blob, §10.6 region blocks, §10.1 slot array and §9.2 gallery fragments, joining the segmented path that already had it (SPEC §11.1 lists every label); cross-implementation vectors pin each label; the TS and Python builders are checked byte-for-byte                                                                                                                                                                                                                                                                                                           | Makes mix-and-match refusals **authenticated** rather than incidental. Most such splices already failed, because they also changed the derived key: stubbing every AAD out leaves exactly three tests failing (a key-mode downgrade, and two slot transplants), and those are the whole of the marginal gain. Says nothing about rollback, which no AEAD can address                                                                                                                                                                                                                                                                         |
| A restored export can be recognised as older than the one you last wrote                        | `--export-number`: a user-supplied counter and a fresh per-export tag inside the encrypted envelope (SPEC §4.1), printed on save and on restore; `src/cli/run.export-number.test.ts` covers the round trip, the per-export tag, the refusals, and that nothing is written to the state directory                                                                                                                                                                                                                                                                                 | **Opt-in, and the tool compares nothing — you do.** It detects a _silent_ replacement only if you remember the number you last wrote; an adversary who can rewrite the vault rewrites the number with it, and nothing stops you reusing a number. **No state is kept on disk.** An earlier design kept a local registry so the machine could compare, which could also catch a rollback you had forgotten about; it was removed because that file proved how many vaults existed and when they were touched. That capability is genuinely lost                                                                                               |
| Released archives can be traced to the workflow and commit that produced them                   | `SHA256SUMS.txt` / `SHA256SUMS-web.txt` over every published archive (`scripts/assemble-cli-release.sh`, `scripts/package-web-bundle.sh`); a Sigstore build-provenance attestation on the CLI archives and the web bundle (`release-cli.yml`, `pages.yml`); every third-party action pinned to a full commit SHA, with the release dry run checking each SHA still resolves upstream; instructions in [CLI.md](CLI.md#verify-your-download)                                                                                                                                      | Proves an artifact came from **a** run of **this** workflow at **a** commit; proves nothing about whether that commit or workflow is benign, and a maintainer or an attacker with write access produces artifacts that verify identically. Builds are **not reproducible** (`deno compile` embeds a V8 snapshot and ignores `SOURCE_DATE_EPOCH`; the archives stamp mtimes), so nobody can rebuild a tag and compare. The binaries are **unsigned**: no notarization, no Authenticode. `SHA256SUMS.txt` is itself neither signed nor attested                                                                                                |
